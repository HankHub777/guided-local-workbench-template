VISUAL GUIDE

從零開始，跟著 LLM 蓋一個屬於自己的工作台

七個段落，對應你實際會走過的七個階段。每一段都可以收合展開，需要動手的地方會附上真實截圖與逐字對話——照著做，不用先想像。

  1. 01 開工前準備：三個工具要先到位 這一步沒辦法靠腳本自動驗證，只能手動確認 ⌄

    後面所有步驟都建立在這三個工具已經裝好的前提上，而這個前提沒辦法用腳本自動檢查——因為要跑檢查腳本，Python 本身就得先存在。如果你的電腦需要 IT 才能裝軟體，先把這三項送出需求；自己的電腦通常直接安裝即可。裝好之後才進入下一步。

    • ✓Python 3.13.2
    • ✓Node.js（LTS 版本）
    • ✓Git
  2. 02 拿到專案：Download ZIP，不走終端機 clone 避開公司內網 407 認證問題的最簡路徑 ⌄

    到模板的 GitHub 頁面，點綠色 Code 按鈕，選 Download ZIP。解壓縮之後，打開終端機切換到那個資料夾。想從這一刻開始留下自己的版本紀錄，可以額外跑一次 git init——這一步是選擇性的。

    〔截圖佔位：Download ZIP 按鈕位置〕
    cd ~/Documents/你的專案名稱
git init

    資料夾裡帶著一支唯讀的環境檢查腳本，不會安裝或更動任何設定，只回報 Python、Node、Git 有沒有偵測到，以及有沒有代理（proxy）相關的環境變數存在。往下走之前先跑一次，能提早抓到後面容易卡住的環境問題。

    python scripts/check_environment.py
  3. 03 選運作模式：用五個商業判斷取代工程術語 不用先搞懂 Local / Managed / Product 是什麼意思 ⌄

    點下面每一題最接近你情況的答案，右下角會給你一個對照建議——實際模式仍以 README 的表格為準。

    • 需要讓其他人也連線進來看嗎？
    • 這平台會不會直接取代掉轉交給下一位同事的人工流程？
    • 這個平台重不重要？
    • 有沒有多個單位、主管會使用？
    • 之後需不需要工程團隊接手維護？
    範例：Managed 示意用結果，實際對照表尚待確認
  4. 04 啟動 LLM 對話：公版 prompt + context bundle 讓 chatbot 真的照模板規則做事，而不是憑印象猜 ⌄

    先在終端機跑一次打包腳本，產生單一檔案上傳給 chatbot；接著用下面這段公版 prompt 起頭，把最後一句換成你自己的狀況。

    python scripts/build_context_bundle.py
    公版 PROMPT · 依你的狀況客製化
    我現在要做一個 clone guided-local-workbench-template 的新專案，我已經在本地建立了資料夾，現在請按照我給你的 LLM_CONTEXT_BUNDLE.md 規則初始化，後續的流程按照模板進行，除非我有特殊要求。如果有遺漏的細節可以參考 https://github.com/HankHub777/guided-local-workbench-template.git
    YOU

    〔上傳 LLM_CONTEXT_BUNDLE.md〕+ 上面那段 prompt

    CHATBOT

    已讀取規則：資料只能經由 web/src/data/ 的 adapter 讀取、data/generated/ 不能手改、改動資料結構要同步更新 schema 與 DATA_CONTRACT.md。目前 ai/PROJECT_CONTEXT.md 還是模板預設內容，建議先告訴我這個工具實際要處理什麼資料，我再開始規劃第一個改動。

    ↑ 示範用對話，實際逐字稿待補

  5. 05 提出一個可驗收的需求 不要一次要求「做一個完整系統」 ⌄

    每次只講一件事，並要求 chatbot 先說清楚會改哪些檔案、哪些驗收條件會過，再讓它動手。

    節點提示 · 貼在你的需求前面
    在你開始改之前，先告訴我：1）你會改哪些檔案 2）改完之後哪些驗收條件會通過。確認過我再讓你動手，先不要直接輸出 patch。
  6. 06 套用 chatbot 的更新，別忘記貼回聊天室 整個流程裡後果最容易被忽略的一步 ⌄

    把 chatbot 輸出的 zip 放進 updates/incoming/，執行 apply_update.py。腳本跑完會印出一段文字，要整段複製貼回聊天室——不然 chatbot 會誤以為變更已經全部套用。

    TERMINAL

    Paste this back into the chatbot so it knows what actually happened: 已套用 3 個檔案，跳過 1 個模板契約檔案（README.md）待你確認。

    YOU

    〔把上面那段整段貼回聊天室〕

    ↑ 示範用對話，實際逐字稿待補

  7. 07 守住模板契約邊界 chatbot 有時候會「順手」幫你改到不該改的檔案 ⌄

    同一份模板會被很多人 clone、交接，模板契約檔案（如 README、ARCHITECTURE_RULES）一旦被順手改掉，之後每份 clone 就會慢慢長成不一樣的東西。

    ✕ 錯誤示範

    順便把 README 也改成我們專案的名字吧

    好的，已經幫你改好 README.md

    ✓ 正確示範

    順便把 README 也改成我們專案的名字吧

    README.md 屬於模板契約檔案，一般專案改動不建議動它。要改的話，我先列出跟 TEMPLATE_BOUNDARY.md 的落差，你確認後再動手，可以嗎？
